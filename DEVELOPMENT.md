# 📘 Руководство по разработке проекта SHIKI MX APP

Данный документ описывает актуальную архитектуру, структуру кодовой базы, правила разработки, локализации, сборки ассетов и ключевые оптимизации проекта.

## 🏗️ 1. Архитектура и структура проекта

## ⚡ 2. ГЛАВНОЕ ПРАВИЛО: Сборка ассетов (`build_assets.py`)

> [!IMPORTANT]
> **Любое изменение файлов в `static/js/*.js` или `static/css/*.css` НЕ отобразится в браузере, пока вы не пересоберёте бандлы!**

В `templates/index.html` и в Service Worker используются скомпилированные файлы:
```html
<link rel="stylesheet" href="/static/bundle.css?v={{ app_version }}">
<script src="/static/bundle.js?v={{ app_version }}"></script>
```

### Команда для пересборки:
```bash
python build_assets.py
```
Что делает скрипт:
1. Объединяет все CSS файлы из `static/css/` в `static/bundle.css` и `static/mobile.css`.
2. Объединяет все JS файлы из `static/js/` в `static/bundle.js` и `static/mobile.js` в строгом порядке зависимостей.
3. Вычисляет MD5-хэш содержимого всех бандлов и обновляет `CACHE_NAME` в `static/sw.js`.
4. При старте `app.py` пересборка бандлов выполняется автоматически.

## 🌐 3. Система переводов и Двуязычие (i18n)

### 3.1. Хранение переводов (`translations.txt`)
Все переводы интерфейса хранятся **исключительно** в файле `translations.txt` в формате:
```text
key = Значение на русском /// English translation
```

### 3.2. Использование переводов в JavaScript:
- Для статических строк используйте функцию `i18n(key, fallback)`:
  ```javascript
  const label = i18n('rates.watching', 'Смотрю');
  ```
- Для условий и выбора названий тайтлов используйте проверку `isEn`:
  ```javascript
  const isEn = typeof getSavedLanguage === 'function' ? (getSavedLanguage() === 'en') : false;
  const title = (isEn && item.name) ? item.name : (item.russian || item.name || '');
  ```

## 🚀 4. Кэширование, параллелизм и SWR архитектура

1. **Stale-While-Revalidate (SWR)**:
   - Все основные вкладки (`/api/tab/explore`, `/api/calendar`, `/api/tab/rates`, `/api/tab/favourites`, `/api/tab/friends`, `/api/tab/history`) отдают закэшированные данные из памяти/SQLite мгновенно (< 3 мс), а свежие данные запрашиваются в фоновом потоке без блокировки UI.
2. **Параллельная загрузка (ThreadPoolExecutor)**:
   - Вкладка `rates`: параллельная выборка чанков GraphQL в 6 потоков.
   - Вкладка `favourites`: параллельная выгрузка 3 категорий (аниме, манга, персонажи) в 3 потока.
   - Вкладка `friends`: параллельная выгрузка друзей и клубов в 2 потока.
3. **Единый GraphQL запрос манги**:
   - `routes/manga.py`: детали манги, роли персонажей и связанные тайтлы запрашиваются одним пакетным GraphQL-запросом вместо 3 последовательных REST-вызовов.
4. **Синхронная инвалидация**:
   - Любое изменение списков пользователя (`POST /api/rate`, `POST /api/rate/increment`, `DELETE /api/rate`) вызывает `invalidate_user_rates_cache()`, синхронно сбрасывая кэш в памяти и БД SQLite.

## 🎬 5. Видеоагрегатор и Document PiP

1. **Мультипровайдерность (`services/video_aggregator.py`)**:
   - Агрегирует потоки из Kodik, AnimeGo, YummyAnime и AniLibria с автоматической дедупликацией озвучек и нумерацией зеркал (`Kodik #1`, `Kodik #2`).
2. **System Document Picture-in-Picture**:
   - Позволяет выносить плеер в системное Always-On-Top окно поверх рабочего стола и любых других окон через Document PiP API.

## 📝 6. Логирование (`logging_config.py`)

- Все события Backend логируются с метками времени, уровнем и модулем.
- Логи одновременно выводятся в консоль и записываются с ротацией в `logs/shikimxapp.log`.
- Запросы API фиксируют размер ответа и время выполнения (с предупреждением `[SLOW_REQ]` для запросов > 1.0с).

# Site Audit — полный обход UI/UX

Задача скилла: **найти максимум дефектов и не потерять ни один**, а не «посмотреть пару страниц».
Правило: сначала карта покрытия, потом данные, потом отчёт. Ничего не правим во время аудита.

## 0. Режим работы

Спроси/определи сам:

1. **Где гоняем** — `http://localhost:5173` (dev), preview или прод?
2. **Есть ли авторизация** — нужен ли тестовый аккаунт или предзагруженная сессия (`--storage-state .auth/user.json`).
3. **Глубина** — быстрый прогон (`--only` / `--viewport`) или полный (все состояния × 3 вьюпорта).
4. **Параллелизм** — `--concurrency 2` (по умолчанию) или `--concurrency 3..4` для ускорения.

Не начинай, пока dev-сервер не отвечает. Проверка: `curl -sI http://localhost:5173` или `Test-NetConnection localhost -Port 5173`.

## 1. Карта покрытия (обязательный шаг)

Аудит без карты = «нашёл 10 проблем из 100». Составь список состояний **до** запуска.

- **SPA с навигацией в состоянии** (как этот проект: `TabKey`, `setActiveTab`): карта = список табов + модалки, открываемые из каждого.
- **URL-роутинг**: карта = `sitemap.xml` / `robots.txt`, затем BFS по внутренним ссылкам.
- **Модалки/дроверы/меню**: это отдельные состояния — проверка шага через `{ "action": "expect", "selector": "..." }`, скрин и проверка для каждого.

Источники карты (в порядке приоритета):

1. `targets.json` в корне скилла/проекта — ручной список (самый точный).
2. `src/components/header/NavigationTabs.tsx` → `TAB_CONFIG` — все табы.
3. `src/App.tsx` — какие вьюхи и модалки рендерятся под каким табом.
4. `sitemap.xml` (если есть).
5. Только потом — автоматический обход ссылок (`crawl`).

Запиши карту в `.audit/coverage.md`: `состояние | как открыть | приоритет | проверено`. Приоритет P0 — то, куда пользователь попадает в первые 30 секунд (главная, каталог, карточка, поиск, вход).

## 2. Запуск

```bash
# один раз
npm i -D playwright @axe-core/playwright
npx playwright install chromium

# стандартный параллельный прогон (Chrome/Edge)
node .agents/skills/site-audit/scripts/audit.mjs --channel chrome --concurrency 2
```

`--channel chrome|msedge` использует уже установленный браузер — не нужно качать Chromium.
`--only <подстрока>` и `--viewport mobile|tablet|desktop` — быстрый частичный прогон.
`--state-timeout <ms>` — лимит времени на шаги состояния (по умолчанию 35000 мс).

Скрипт по каждому состоянию и вьюпорту изолированно собирает:

| Что | Как |
|---|---|
| a11y (контраст, alt, роли, labels, порядок заголовков) | `@axe-core/playwright`, WCAG 2.2 AA + перцептивная калибровка APCA (W3C 0.98G Lc) |
| живой UX (модалки, сдвиги макета, клавиатура) | Live UX: замер CLS, блокировка body-скролла при модалке, тест Escape-закрытия |
| горизонтальный скролл / вылезающие элементы | геометрия DOM (унифицированное правило `horizontal-scroll`) |
| обрезанный текст | `scrollWidth > clientWidth` (с исключением экранных ридеров `.sr-only`) |
| мелкие тач-таргеты | строгое разделение (<24px P2 vs 24..43px P3) и умная группировка компактных чипов |
| слишком мелкий шрифт (< 12px) | computed style |
| битые картинки | `naturalWidth === 0` |
| ошибки JS и упавшие запросы (4xx/5xx) | console + network |
| перехват кликов оверлеями (`agentation`, тулбары, тосты) | фиксация дефекта `pointer-intercepted` с изоляцией активных модалок |
| скриншот полной страницы | `isMobile: true`, `hasTouch: true`, отключённые анимации |

Результат: `.audit/audit.json`, `.audit/report.md` (структурированный отчёт по шаблону с оценкой усилий S/M/L и стабильными ID `A-<md5>`), `.audit/shots/*.png`.

> Скрипт — чёрный ящик. Не читай его целиком, чтобы сэкономить контекст: запусти с `--help`.

## 3. Ручной проход (то, что скрипт не увидит)

После автоматики **обязательно** пройди руками по чеклисту `references/checklist.md`. Автоматика не ловит:

- пустые состояния (0 результатов, нет избранного, ошибка сети);
- поведение при загрузке (скелетоны, мигание, layout shift);
- фокус и клавиатуру (`Tab`, `Esc` в модалках, focus trap, возврат фокуса);
- длинные строки: название из 200 символов, эмодзи, RTL, другой язык;
- скролл внутри модалки и на мобиле, `100vh` vs адресная строка;
- hover/active/disabled/loading/error для каждой интерактивной мелочи;
- тексты: опечатки, «undefined», «null», «[object Object]».

Ручной проход делай встроенным браузером/MCP (Playwright MCP, Chrome DevTools MCP) — по одному состоянию, с фиксацией шагов воспроизведения.

## 4. Дедупликация и приоритеты

- Один дефект = одна запись со стабильным детерминированным ID (`A-<md5>`), даже если он на 40 карточках: `правило + селектор`, в поле «где» — список страниц.
- Приоритеты:
  - **P1 (blocker)** — не работает, ломает вёрстку на мобиле, ошибка JS, недоступно с клавиатуры, контраст < 3:1 на основном тексте, 4xx/5xx.
  - **P2 (major)** — тач-таргет < 44px, контраст 3:1..4.5:1, обрезанный текст, отсутствие alt, скачки фокуса, пустое состояние без объяснения.
  - **P3 (minor)** — отступы, выравнивание, мелкая типографика, консистентность иконок, микрокопия.
- Не раздувай: если сомневаешься между P2 и P3 — ставь P3, но **не выкидывай**.
- Оценивай «усилие»: S / M / L — чтобы можно было чинить по порядку.

## 5. Отчёт

Генерируется автоматически скриптом или вручную по шаблону `references/report-template.md`. Обязательные части:

1. **Контекст и охват**: дата, стенд, глубина, используемый браузер и движок.
2. **Покрытие**: матрица состояний и вьюпортов (успех/ошибка с таймаутом).
3. **Сводка**: P1/P2/P3 + распределение по усилиям (S/M/L) + топ-5 «чинить первым».
4. **Таблица дефектов**: `ID | P | Усилие | Где | Правило | Проблема | Скриншот`.
5. **Скриншоты**: галерея экранов из `.audit/shots/...`.
6. **Приложение**: сводный лог нарушений axe-core.

## 6. Ограничения

- Не логинись реальными аккаунтами, не удаляй данные, не оформляй заказы. Только чтение и безопасные клики.
- Не трогай аналитику/платежи. Если состояние требует оплаты — пропусти и отметь в покрытии.
- Лимит времени на состояние контролируется параметром `--state-timeout` (по умолчанию 35 сек).
- Не правь код приложения во время аудита. Находки → отчёт → отдельная задача на исправление.

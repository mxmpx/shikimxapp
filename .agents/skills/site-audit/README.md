# site-audit — скилл для Google Antigravity

Полный обход сайта/SPA и сбор дефектов UI/UX: a11y, адаптивность, состояния, консоль, сеть.
Формат — открытый стандарт Agent Skills (`SKILL.md`), работает в **AGY / AGY CLI / AGY IDE** без изменений.

## Куда положено

```
<workspace-root>/.agents/skills/site-audit/
├── SKILL.md                      # инструкции агенту (что и в каком порядке делать)
├── targets.json                  # карта состояний ЭТОГО проекта (табы, мобильная навигация, модалки)
├── targets.example.json          # нейтральный пример (роутинг + формы)
├── scripts/audit.mjs             # Playwright + axe-core: изолированный обход, скрины, отчёт
└── references/
    ├── checklist.md              # 70+ эвристик для ручного прохода
    └── report-template.md        # шаблон структурированного отчёта
```

`.agents/skills/` — путь по умолчанию для Antigravity; `.agent/skills/` поддержан для совместимости.
Глобально (для всех проектов) — `~/.gemini/config/skills/site-audit/` (единственный путь, который видят все три оболочки).

## Установка зависимостей (один раз)

```bash
npm i -D playwright @axe-core/playwright
npx playwright install chromium
```

Браузеры уже могут быть в `%LOCALAPPDATA%\ms-playwright` — тогда второй шаг не нужен.
Не хочешь качать Chromium — используй установленный Chrome/Edge: добавь `--channel chrome` (или `msedge`).

## Запуск

```bash
# 1. поднять приложение
npm run dev

# 2. полный прогон по карте состояний (по умолчанию параллельно 2 потока)
node .agents/skills/site-audit/scripts/audit.mjs

# ускоренный параллельный прогон в 3-4 потока с системным Chrome
node .agents/skills/site-audit/scripts/audit.mjs --channel chrome --concurrency 3

# быстрый вариант: одно состояние на одном вьюпорте
node .agents/skills/site-audit/scripts/audit.mjs --only home --viewport mobile --channel chrome

# прогон с предзагруженной сессией (авторизация)
node .agents/skills/site-audit/scripts/audit.mjs --storage-state .auth/user.json

# всё, кроме axe и скриншотов
node .agents/skills/site-audit/scripts/audit.mjs --no-axe --no-shots
```

> Без аргументов скрипт сразу запускает стандартный аудит по `targets.json`.
> `--only` фильтрует по подстроке: `--only home` захватит и `home`, и `mobile-home`.

Результат: `.audit/report.md` (соответствует `report-template.md`), `.audit/audit.json`, `.audit/shots/*.png`.

## Ключевые возможности раннера

1. **Изоляция окружения**: Каждая пара состояние × вьюпорт открывается в свежем `browser.newContext()` — тема, куки и локальные хранилища не протекают между тестами.
2. **Честная эмуляция устройств**: Для мобильных и планшетов активируются `isMobile: true`, `hasTouch: true` и `deviceScaleFactor: 2..3`. Это гарантирует срабатывание медиавыражений `@media (pointer: coarse)` и корректность тач-событий.
3. **Фильтрация шума и группировка чипов**: Проверка тач-таргетов строго разделяет критические нарушения (<24px по WCAG 2.5.8 AA — P2) и компактные чипы/фильтры (24..43px по Apple HIG — P3). Повторяющиеся чипы в группах (например, жанры или фильтры каталога) агрегируются в одну сводную запись вместо спама сотней строк.
4. **Перцептивный контраст APCA (W3C 0.98G)**: Вместо устаревшей формулы WCAG 2.1, дающей ложные тревоги на тёмных темах, используется перцептивный алгоритм APCA. Текст с достаточной читаемостью (Lc ≥ 60 для основного, Lc ≥ 45 для вторичного) не создаёт ложных P2-дефектов.
5. **Активный интерактивный аудит (Live UX Heuristics)**: Раннер тестирует реальный UX: замеряет сдвиги макета (CLS по Core Web Vitals), проверяет блокировку скролла фона (`body overflow: hidden`) при открытых модалках и тестирует закрытие окон по нажатию клавиши `Escape`.
6. **Детерминированные стабильные ID**: Всем проблемам присваивается неизменный хеш-идентификатор вида `A-<md5>` (по правилу, селектору и сообщению), что предотвращает скачки ID при повторных прогонах.
7. **Быстрый селекторный фоллбэк**: Если первый селектор из массива вариантов отсутствует или скрыт на мобильном экране, раннер мгновенно проверяет альтернативы через `locator.count()` и `:visible`, не ожидая дефолтного таймаута Playwright.
8. **Фиксация перехвата кликов**: При блокировке клика оверлеями фиксируется дефект `pointer-intercepted` с последующим аварийным кликом для завершения сценария.
9. **Шаг проверки `expect` / `assert`**: Возможность проверить появление диалога или элемента (`expect`) перед фиксацией состояния.
10. **Пул параллельных воркеров**: Параметр `--concurrency <n>` (по умолчанию 2) ускоряет аудит в 2–3 раза.

## Параметры командной строки

| Опция | Описание | По умолчанию |
|---|---|---|
| `--targets <path>` | Путь к конфигурации состояний | `targets.json` |
| `--base <url>` | Базовый URL приложения | из config или `http://localhost:5173` |
| `--only <name>` | Фильтр по названию состояния | все |
| `--viewport <name>` | Фильтр по имени вьюпорта (`mobile`, `tablet`, `desktop`) | все |
| `--concurrency <n>` | Количество параллельных вкладок-воркеров (1-4) | `2` |
| `--state-timeout <ms>` | Предельное время выполнения шагов одного состояния | `35000` |
| `--storage-state <path>` | Файл состояния авторизации Playwright (cookies + localStorage) | нет |
| `--ignore <rules>` | Игнорируемые правила аудита через запятую | нет |
| `--sample-limit <n>` | Лимит примеров элементов на одно правило в отчёте | `5` |
| `--channel <name>` | Браузерный канал Playwright (`chrome`, `msedge`) | Chromium |
| `--no-axe` | Отключить сканирование Axe accessibility | включено |
| `--no-shots` | Не сохранять скриншоты | скриншоты включены |
| `--headless` | Режим работы без окна | `true` |

## Как расширять карту состояний (`targets.json`)

```json
{
  "name": "modal-anime-card",
  "viewports": ["tablet", "desktop"],
  "steps": [
    { "action": "click", "selector": ["main div[role=\"button\"]", ".anime-card"] },
    { "action": "expect", "selector": "[role=\"dialog\"], #anime-modal-title", "timeout": 5000 },
    { "action": "wait", "ms": 400 }
  ]
}
```

Поддерживаемые действия шагов:
- `click`: клик с авто-детекцией перехвата клика и быстрым fallback по массиву селекторов.
- `expect` / `assert`: ожидание видимости селектора (предотвращает ложные скрины при сорвавшихся переходах).
- `hover`: наведение курсора мыши.
- `fill`: ввод текста (`value`).
- `press`: нажатие клавиши (`key`, по умолчанию `Enter`).
- `wait`: пауза в миллисекундах (`ms`).
- `goto`: прямой переход по относительному или абсолютному URL (`url`).

## Что скрипт НЕ заменяет

Пустые состояния, клавиатуру (focus trap, возврат фокуса при закрытии модалок), длинные нестандартные строки, микрокопию — это ручной проход по `references/checklist.md`.
